01
The Problem Aggregation Solves
Why your find() + JS loops don't scale

Here's a real question on this dataset: which city has the most verified users, and what's the average follower count of those verified users in that city?

You know CRUD. So you solve it the only way you know — fetch everything, loop in JavaScript, and hope the dataset stays small.

The Painful Way

JavaScript — client-side 
// Step 1: Fetch ALL 8 users from the database
const allUsers = await db.collection('users').find({}).toArray();

// Step 2: Filter verified users in JS — 3 docs pulled for nothing
const verified = allUsers.filter(u => u.isVerified);
// → [u1, u2, u4, u6, u8] — 5 docs kept, 3 wasted bandwidth

// Step 3: Group by city manually
const byCity = {};
for (const u of verified) {
  if (!byCity[u.city]) byCity[u.city] = [];
  byCity[u.city].push(u);
}
// → { Bhopal: [u1, u6], Indore: [u2, u4, u8] }

// Step 4: Compute count + average per city
const results = Object.entries(byCity).map(([city, users]) => ({
  city,
  verifiedCount: users.length,
  avgFollowers: users.reduce((sum, u) => sum + u.followersCount, 0) / users.length
}));
// → [
//   { city: "Bhopal", verifiedCount: 2, avgFollowers: 1650 },
//   { city: "Indore", verifiedCount: 3, avgFollowers: 5566.67 }
// ]

// Step 5: Sort by count descending
results.sort((a, b) => b.verifiedCount - a.verifiedCount);

// Step 6: Grab the winner
console.log(results[0]);
// → { city: "Indore", verifiedCount: 3, avgFollowers: 5566.67 }
⚠️

Six steps. 20+ lines. Every document fetched over the wire. If users grows to 10 million, you're pulling 10 million documents to filter 3 million away. The database ships data you throw in the trash.

The Aggregation Way

Same result. Four stages. The database does all the work — only the final row crosses the network.

mongosh 
db.users.aggregate([
  { $match:  { isVerified: true } },
  { $group:  {
    _id: "$city",
    verifiedCount: { $sum: 1 },
    avgFollowers:  { $avg: "$followersCount" }
  }},
  { $sort:   { verifiedCount: -1 } },
  { $limit:  1 }
])
Output 
[
  { _id: "Indore", verifiedCount: 3, avgFollowers: 5566.666666666667 }
]

One document returned. The filtering, grouping, averaging, sorting — all happened inside MongoDB. The aggregation framework is a pipeline: you feed it stages, documents flow through each one, and what comes out the other end is your answer.

02
The Mental Model
Pipeline = array of stages. Output of stage N = input of stage N+1.
Key Concept

A pipeline is an array. Each element is a stage — a single operation like filter, group, or sort. Documents enter the first stage, get transformed, and the entire output of that stage becomes the input to the next. If stage 1 outputs 5 documents, stage 2 receives exactly 5 documents. No more, no less — unless a stage itself changes the count (like $group collapsing many into few, or $unwind splitting one into many).

12 posts enter the pipeline
Full posts collection — all 12 documents flow in.
$match: { category: "tech" }
8 documents dropped. 3 tech posts exit: p1, p6, p10.
$sort: { likesCount: -1 }
Still 3 documents — just reordered: p10 (670), p6 (560), p1 (340).
$limit: 1
2 documents dropped. 1 exits: p10.
Result: 1 document
Only this 1 document crosses the network to your app.
💡

Order matters. $match before $group means fewer documents to group. $limit after $sort means you get the true top N. Swap them and you get garbage. Think of it like a Unix pipe — each stage feeds the next.

03
$match
Filter documents — the WHERE clause of aggregation

Without it: you pull every document from the collection and discard the ones you don't need in JS. With 8 users that's fine. With 8 million, your app crashes before the loop finishes.

What it does: passes through only documents that match your criteria. Identical syntax to find() query operators. Put it first whenever possible — MongoDB can use indexes on $match, and earlier filtering means every subsequent stage processes fewer documents.

Example 1 — Verified users only

mongosh 
db.users.aggregate([
  { $match: { isVerified: true } }
])
Output — 5 documents 
[
  { _id: "u1", name: "Aarav Sharma",  ... isVerified: true, followersCount: 1200 },
  { _id: "u2", name: "Diya Patel",    ... isVerified: true, followersCount: 4500 },
  { _id: "u4", name: "Ananya Rao",    ... isVerified: true, followersCount: 8900 },
  { _id: "u6", name: "Ishita Verma",  ... isVerified: true, followersCount: 2100 },
  { _id: "u8", name: "Myra Kapoor",   ... isVerified: true, followersCount: 3300 }
]

Example 2 — Food or tech posts with 800+ likes

mongosh 
db.posts.aggregate([
  { $match: {
    likesCount: { $gt: 800 },
    category:   { $in: ["tech", "food"] }
  }}
])
Output — 2 documents 
[
  { _id: "p3", userId: "u4", caption: "Best butter chicken in Indore, change my mind", likesCount: 1200, category: "food", ... },
  { _id: "p9", userId: "u4", caption: "Street food tour of Indore, thread",            likesCount: 2100, category: "food", ... }
]
⚠️

Always put $match as early as possible. MongoDB can use indexes to satisfy a $match at the start of a pipeline. Once you run a $project or $group before $match, the optimizer can't use indexes — it has to scan every document. This is the #1 performance mistake in aggregation.

04
$group
Collapse many documents into fewer — the GROUP BY of MongoDB

Without it: you fetch all posts, loop through them in JS, maintain a dictionary keyed by category, and compute sums/averages yourself. It works, but the database has to ship every document to your app, and your JS is single-threaded.

What it does: groups input documents by a specified key (_id) and applies accumulator operators to each group. The output is one document per unique group value.

Example 1 — Count posts per category

mongosh 
db.posts.aggregate([
  { $group: {
    _id: "$category",
    postCount: { $sum: 1 }
  }}
])
Output — 5 documents (one per category) 
[
  { _id: "tech",    postCount: 3 },
  { _id: "travel",  postCount: 3 },
  { _id: "food",    postCount: 2 },
  { _id: "fitness", postCount: 2 },
  { _id: "art",     postCount: 2 }
]

Example 2 — Total + average likes per category

mongosh 
db.posts.aggregate([
  { $group: {
    _id: "$category",
    totalLikes: { $sum: "$likesCount" },
    avgLikes:   { $avg: "$likesCount" },
    postCount:  { $sum: 1 }
  }},
  { $sort: { totalLikes: -1 } }
])
Output — sorted by totalLikes descending 
[
  { _id: "food",    totalLikes: 3300, avgLikes: 1650,    postCount: 2 },
  { _id: "travel",  totalLikes: 3290, avgLikes: 1096.67, postCount: 3 },
  { _id: "tech",    totalLikes: 1570, avgLikes: 523.33,  postCount: 3 },
  { _id: "fitness", totalLikes: 990,  avgLikes: 495,     postCount: 2 },
  { _id: "art",     totalLikes: 740,  avgLikes: 370,     postCount: 2 }
]
⚠️

$group does not preserve document order. The output order is arbitrary unless you add a $sort after. Also, grouping by null (_id: null) collapses all documents into a single group — useful for counting an entire collection.

05
$project
Reshape documents — pick, drop, and compute fields

Without it: every document ships over the wire with all 9 fields, even if your frontend only needs 2. You're paying bandwidth and serialization costs for data you throw away.

What it does: passes through documents with only the fields you specify. Use 1 to include, 0 to exclude. You can also compute new fields — expressions make $project the stage where data gets reshaped, not just trimmed.

Example 1 — Pick only name and username

mongosh 
db.users.aggregate([
  { $project: { _id: 0, name: 1, username: 1 } }
])
Output — 8 documents, 2 fields each 
[
  { name: "Aarav Sharma",  username: "aarav_codes"  },
  { name: "Diya Patel",    username: "diya.travels" },
  { name: "Kabir Singh",   username: "kabir_fit"    },
  { name: "Ananya Rao",    username: "ananya.eats"  },
  { name: "Vihaan Gupta",  username: "vihaan_art"   },
  { name: "Ishita Verma",  username: "ishita.codes" },
  { name: "Reyansh Joshi", username: "rey_travels"  },
  { name: "Myra Kapoor",   username: "myra.fitlife" }
]

Example 2 — Compute engagement (likes + comments)

mongosh 
db.posts.aggregate([
  { $project: {
    _id: 1,
    caption: 1,
    engagement: { $add: ["$likesCount", "$commentsCount"] }
  }}
])
Output — 12 documents 
[
  { _id: "p1",  caption: "Deployed my first MERN app today!",        engagement: 343  },
  { _id: "p2",  caption: "Sunset in Manali, worth every step",       engagement: 892  },
  { _id: "p3",  caption: "Best butter chicken in Indore...",         engagement: 1204 },
  { _id: "p4",  caption: "Leg day never lies",                       engagement: 211  },
  { _id: "p5",  caption: "New charcoal sketch, took 6 hours",        engagement: 432  },
  { _id: "p6",  caption: "Understanding closures finally clicked",   engagement: 563  },
  { _id: "p7",  caption: "Road trip through Spiti valley",           engagement: 1450 },
  { _id: "p8",  caption: "5AM workout hits different",               engagement: 782  },
  { _id: "p9",  caption: "Street food tour of Indore, thread",       engagement: 2100 },
  { _id: "p10", caption: "MongoDB aggregation is actually beautiful", engagement: 673 },
  { _id: "p11", caption: "Backwaters of Kerala at dawn",            engagement: 950  },

You cannot mix 1 and 0 freely. Once you include a field with 1, all other fields are excluded by default — you can only use 0 to explicitly remove _id. The exception: if you set only exclusions (all 0), the rest come along. This is the most common $project mistake.

06
$sort
Order documents by one or more fields

Without it: you fetch all documents, then call .sort() in JS on the full array. Fine for 12 posts, catastrophic for 12 million. The database has an internal sort that's dramatically faster.

What it does: reorders all incoming documents. Use 1 for ascending, -1 for descending. Multiple fields are sorted lexicographically — first field first, ties broken by second, etc.

Example 1 — Posts by likes descending

mongosh 
db.posts.aggregate([
  { $sort: { likesCount: -1 } }
])
Output — top 5 shown 
[
  { _id: "p9",  likesCount: 2100, caption: "Street food tour of Indore, thread", ... },
  { _id: "p7",  likesCount: 1450, caption: "Road trip through Spiti valley",      ... },
  { _id: "p3",  likesCount: 1200, caption: "Best butter chicken in Indore...",    ... },
  { _id: "p11", likesCount: 950,  caption: "Backwaters of Kerala at dawn",       ... },
  { _id: "p2",  likesCount: 890,  caption: "Sunset in Manali, worth every step", ... }
]

Example 2 — Users by followers ascending, then age descending

mongosh 
db.users.aggregate([
  { $sort: { followersCount: 1, age: -1 } },
  { $project: { name: 1, followersCount: 1, age: 1, _id: 0 } }
])
Output — 8 documents 
[
  { name: "Vihaan Gupta",  followersCount: 150,  age: 21 },
  { name: "Kabir Singh",   followersCount: 320,  age: 28 },
  { name: "Reyansh Joshi", followersCount: 600,  age: 26 },
  { name: "Aarav Sharma",  followersCount: 1200, age: 22 },
  { name: "Ishita Verma",  followersCount: 2100, age: 23 },
  { name: "Myra Kapoor",   followersCount: 3300, age: 27 },
  { name: "Diya Patel",    followersCount: 4500, age: 25 },
  { name: "Ananya Rao",    followersCount: 8900, age: 24 }
]
⚠️

$sort has a 100MB memory limit by default. If the pipeline is sorting more data than fits in memory, MongoDB throws an error. Add { allowDiskUse: true } as a second argument to aggregate() to let it spill to disk. Better: always $match before $sort to reduce the input size.

07
$limit
Pass through only the first N documents

Without it: you fetch all 12 posts to display a "Top 3" leaderboard. 9 documents crossed the network for nothing.

What it does: passes through at most N documents, drops the rest. Pair with $sort to get "top N" — but $sort must come before $limit, or you're limiting random documents then sorting what's left.

Example — Top 3 most liked posts

mongosh 
db.posts.aggregate([
  { $sort:  { likesCount: -1 } },
  { $limit: 3 },
  { $project: { caption: 1, likesCount: 1, _id: 0 } }
])
Output — 3 documents 
[
  { caption: "Street food tour of Indore, thread", likesCount: 2100 },
  { caption: "Road trip through Spiti valley",      likesCount: 1450 },
  { caption: "Best butter chicken in Indore...",    likesCount: 1200 }
]
08
$skip
Discard the first N documents, pass through the rest

What it does: removes the first N documents from the current pipeline result. It is commonly paired with $sort and $limit for pagination.

Example — Page 2, 3 posts per page

mongosh 
db.posts.aggregate([
  { $sort: { likesCount: -1, _id: 1 } },
  { $skip: 3 },
  { $limit: 3 },
  { $project: { caption: 1, likesCount: 1, _id: 0 } }
])
Output — page 2 
[
  { caption: "Best butter chicken in Indore...", likesCount: 1200 },
  { caption: "Backwaters of Kerala at dawn",    likesCount: 950 },
  { caption: "Sunset in Manali, worth every step", likesCount: 890 }
]
⚠️

Pagination formula: skip = (page - 1) * pageSize. For large offsets, cursor/range pagination is often more scalable than repeatedly skipping thousands of documents.

09
$unwind
Turn one array field into multiple documents

What it does: if one document contains an array, $unwind creates one output document for every array element.

Example — One post with three tags

mongosh 
db.posts.aggregate([
  { $match: { _id: "p1" } },
  { $unwind: "$tags" },
  { $project: { _id: 0, caption: 1, tag: "$tags" } }
])
Output — 3 documents 
[
  { caption: "Deployed my first MERN app today!", tag: "mern" },
  { caption: "Deployed my first MERN app today!", tag: "webdev" },
  { caption: "Deployed my first MERN app today!", tag: "nodejs" }
]
💡

Important: $unwind can increase the document count dramatically. Use preserveNullAndEmptyArrays: true when documents without an array value must remain in the result.

10
$lookup
Join documents from another collection

What it does: performs a left outer join. The matching documents from another collection are placed into an array field.

Example — Attach the author to every post

mongosh 
db.posts.aggregate([
  { $lookup: {
    from: "users",
    localField: "userId",
    foreignField: "_id",
    as: "author"
  }},
  { $unwind: "$author" },
  { $project: {
    _id: 0,
    caption: 1,
    authorName: "$author.name",
    username: "$author.username"
  }}
])
Output — first matching document 
{
  caption: "Deployed my first MERN app today!",
  authorName: "Aarav Sharma",
  username: "aarav_codes"
}
⚠️

Think: $lookup is the aggregation equivalent of saying “find the related document and attach it here.” Index the foreign field when appropriate, and keep the joined dataset under control.

11
$graphLookup
Follow recursive relationships such as a hierarchy

What it does: performs a recursive search through a collection. It is useful for parent/child structures such as employees, categories, or referral trees.

Example pattern — Follow a manager hierarchy

mongosh 
db.employees.aggregate([
  { $match: { _id: "e1" } },
  { $graphLookup: {
    from: "employees",
    startWith: "$managerId",
    connectFromField: "managerId",
    connectToField: "_id",
    as: "managementChain"
  }}
])
💡

Key idea: $graphLookup is for recursive traversal, not a normal one-level join. The options startWith, connectFromField, and connectToField define how the traversal moves.

12
$addFields / $set
Add or overwrite fields without removing the existing document

What it does: calculates new fields while keeping the other fields. $set is an alias for $addFields.

Example — Calculate engagement

mongosh 
db.posts.aggregate([
  { $set: {
    engagement: {
      $add: ["$likesCount", "$commentsCount"]
    }
  }}
])
Example result 
{
  _id: "p1",
  likesCount: 340,
  commentsCount: 3,
  engagement: 343
}
💡

$set vs $project: use $set when you want to keep the existing document and add/overwrite fields. Use $project when you intentionally reshape which fields leave the stage.

13
$unset
Remove fields from pipeline documents

What it does: removes one or more fields from each document. It is an alias-style convenience for excluding fields from the pipeline output.

Example — Remove email before sending user data

mongosh 
db.users.aggregate([
  { $unset: ["email", "followersCount"] }
])
💡

API use: $unset is useful near the end of a pipeline when sensitive or unnecessary fields should not reach the application layer.

14
$replaceRoot
Replace the whole document with an embedded document

What it does: promotes an embedded object to become the new root document.

Example — Promote the joined author

mongosh 
db.posts.aggregate([
  { $lookup: {
    from: "users",
    localField: "userId",
    foreignField: "_id",
    as: "author"
  }},
  { $unwind: "$author" },
  { $replaceRoot: { newRoot: "$author" } }
])
💡

Remember: replacing the root discards the old top-level shape unless you deliberately merge fields first. For many APIs, $project is safer when you only need a few fields.

15
$out
Write the pipeline result into a collection

What it does: sends the final aggregation result to a collection instead of returning it to the application in the normal way.

mongosh 
db.posts.aggregate([
  { $group: {
    _id: "$category",
    totalLikes: { $sum: "$likesCount" }
  }},
  { $out: "categoryStats" }
])
⚠️

Use carefully: $out is a write stage. It is useful for materializing reports or derived collections, but it should not be casually placed in a request pipeline.

16
$merge
Write aggregation results into a collection with controlled merge behavior

What it does: writes results to a target collection and lets you define what happens when a matching document already exists.

mongosh 
db.posts.aggregate([
  { $group: {
    _id: "$category",
    totalLikes: { $sum: "$likesCount" },
    postCount: { $sum: 1 }
  }},
  { $merge: {
    into: "categoryStats",
    on: "_id",
    whenMatched: "replace",
    whenNotMatched: "insert"
  }}
])
💡

$out vs $merge: both write results. $merge gives finer control over existing documents and is useful for incremental or repeatable materialization.

17
$count
Count the documents reaching this point

What it does: returns one document containing the number of documents that entered the stage.

mongosh 
db.posts.aggregate([
  { $match: { category: "tech" } },
  { $count: "totalTechPosts" }
])
Output 
[
  { totalTechPosts: 3 }
]
💡

Important: $count counts documents after all previous stages. So put $match, $unwind, or other filtering stages before it when the count must reflect those transformations.

18
$sample
Pick random documents from the pipeline

What it does: randomly selects a specified number of documents.

mongosh 
db.posts.aggregate([
  { $sample: { size: 3 } },
  { $project: { caption: 1, category: 1, _id: 0 } }
])
💡

Use cases: random recommendations, demo data, experimentation, or sampling a large collection. The exact output changes because the selection is random.

19
$facet
Run multiple independent pipelines over the same input

What it does: runs multiple aggregation pipelines in parallel on the same input documents and returns their results in separate arrays.

Example — Dashboard in one query

mongosh 
db.posts.aggregate([
  { $facet: {
    topPosts: [
      { $sort: { likesCount: -1 } },
      { $limit: 3 },
      { $project: { caption: 1, likesCount: 1, _id: 0 } }
    ],
    categoryCounts: [
      { $group: { _id: "$category", count: { $sum: 1 } } }
    ]
  }}
])
💡

Mental model: one input stream enters $facet; several independent branches consume it; one document comes out containing the branch results.

20
$bucket
Group numeric values into explicit ranges

What it does: groups documents into numeric ranges defined by your boundaries.

mongosh 
db.users.aggregate([
  { $bucket: {
    groupBy: "$age",
    boundaries: [20, 24, 28, 32],
    default: "other",
    output: {
      count: { $sum: 1 },
      avgFollowers: { $avg: "$followersCount" }
    }
  }}
])
💡

Boundary rule: the lower boundary is inclusive and the upper boundary is exclusive for each bucket. Always provide a default bucket when values may fall outside your boundaries.

21
$bucketAuto
Let MongoDB calculate roughly even-sized numeric buckets

What it does: automatically chooses bucket boundaries for a requested number of buckets.

mongosh 
db.users.aggregate([
  { $bucketAuto: {
    groupBy: "$followersCount",
    buckets: 4,
    output: {
      count: { $sum: 1 },
      avgAge: { $avg: "$age" }
    }
  }}
])
💡

$bucket vs $bucketAuto: choose $bucket when your ranges have business meaning; choose $bucketAuto when you want MongoDB to distribute values into approximately even buckets.

22
Accumulators
Calculate values inside $group and other accumulation stages

Accumulators combine values from multiple input documents. The most important ones for backend work are $sum, $avg, $min, $max, $first, $last, and $push.

mongosh 
db.posts.aggregate([
  { $group: {
    _id: "$category",
    totalLikes: { $sum: "$likesCount" },
    avgLikes: { $avg: "$likesCount" },
    minLikes: { $min: "$likesCount" },
    maxLikes: { $max: "$likesCount" },
    captions: { $push: "$caption" }
  }}
])
Accumulator Meaning Simple idea
$sum Adds values total likes / count with 1
$avg Average average price, likes, age
$min / $max Smallest / largest lowest and highest value
$push Builds an array collect values from each group
$addToSet Builds a unique array remove duplicate values
💡

Interview tip: { $sum: 1 } means “add one for every document”, so it is a common way to count documents inside $group.

23
Arithmetic Operators
Perform calculations inside pipeline expressions

Arithmetic expressions are used to calculate derived values without pulling the documents into JavaScript.

mongosh 
db.posts.aggregate([
  { $project: {
    _id: 0,
    caption: 1,
    engagement: { $add: ["$likesCount", "$commentsCount"] },
    doubleLikes: { $multiply: ["$likesCount", 2] }
  }}
])
Operator Use
$add Add numbers
$subtract Subtract one value from another
$multiply Multiply values
$divide Divide values
$mod Remainder
$round Round a number
24
Comparison Operators
Compare fields and values inside expressions

Comparison operators return boolean results and are commonly used inside $expr, $project, $set, and conditional expressions.

mongosh 
db.users.aggregate([
  { $project: {
    name: 1,
    _id: 0,
    isPopular: { $gte: ["$followersCount", 2000] }
  }}
])
Operator Meaning
$eq equal
$ne not equal
$gt / $gte greater than / greater than or equal
$lt / $lte less than / less than or equal
25
Logical Operators
Combine boolean conditions

Logical operators let you combine multiple boolean expressions.

mongosh 
db.users.aggregate([
  { $match: {
    $or: [
      { city: "Bhopal" },
      { city: "Indore" }
    ],
    isVerified: true
  }}
])
Operator Meaning
$and all conditions must be true
$or at least one condition is true
$not negates a condition
$nor none of the conditions are true
26
String Operators
Transform and inspect text inside the pipeline

String operators are useful for search normalization, display fields, labels, and computed API responses.

mongosh 
db.users.aggregate([
  { $project: {
    _id: 0,
    name: 1,
    usernameLower: { $toLower: "$username" },
    nameLength: { $strLenCP: "$name" }
  }}
])
Operator Use
$concat join strings
$toLower / $toUpper change case
$substrCP take part of a string
$strLenCP count Unicode code points
$trim remove surrounding characters/whitespace
27
Array Operators
Inspect, transform, and filter array fields

Array operators are especially important when your MongoDB documents contain tags, sizes, cart items, comments, or other embedded arrays.

mongosh 
db.posts.aggregate([
  { $project: {
    _id: 0,
    caption: 1,
    tagCount: { $size: "$tags" },
    firstTag: { $arrayElemAt: ["$tags", 0] }
  }}
])
Operator Use
$size array length
$arrayElemAt read an element by index
$in check whether a value exists in an array
$filter keep only matching array elements
$map transform every array element
28
Date Operators
Extract and calculate date/time information

For production applications, store dates as MongoDB Date values rather than plain strings when you need date arithmetic, sorting, or date-based filtering.

mongosh 
db.posts.aggregate([
  { $project: {
    _id: 0,
    caption: 1,
    year: { $year: "$createdAt" },
    month: { $month: "$createdAt" },
    day: { $dayOfMonth: "$createdAt" }
  }}
])
💡

Practical rule: date operators expect compatible date values. If your database currently stores ISO dates as strings, consider converting them deliberately with $dateFromString or, preferably, storing future records as actual BSON dates.

29
Type Conversion Operators
Convert values to the type your next expression needs

Aggregation often receives mixed types, especially when data comes from APIs or older collections. Type conversion lets you make expressions predictable.

mongosh 
db.orders.aggregate([
  { $set: {
    numericPrice: { $toDouble: "$price" },
    numericQuantity: { $toInt: "$quantity" }
  }},
  { $set: {
    total: { $multiply: ["$numericPrice", "$numericQuantity"] }
  }}
])
Operator Typical conversion
$toInt integer
$toDouble floating-point number
$toString string
$toObjectId ObjectId
$convert full control with onError/onNull
30
Variables
Store intermediate values with $$ variables

MongoDB aggregation variables are referenced with $$. Built-in variables and variables introduced by operators such as $let help make complex expressions easier to read.

mongosh 
db.posts.aggregate([
  { $project: {
    _id: 0,
    caption: 1,
    score: {
      $let: {
        vars: {
          likes: "$likesCount",
          comments: "$commentsCount"
        },
        in: {
          $add: ["$$likes", "$$comments"]
        }
      }
    }
  }}
])
💡

Remember: field references use $fieldName; aggregation variables use $$variableName. Confusing one dollar with two dollars is a common beginner error.

31
Combined Pipelines
Put the stages together to solve real backend questions
Case 1 — Find the top 2 verified users by follower count
Pipeline 
db.users.aggregate([
  { $match: { isVerified: true } },
  { $sort: { followersCount: -1, _id: 1 } },
  { $limit: 2 },
  { $project: {
    _id: 0,
    name: 1,
    username: 1,
    followersCount: 1
  }}
])
Case 2 — Count posts and total likes for every category
Pipeline 
db.posts.aggregate([
  { $group: {
    _id: "$category",
    postCount: { $sum: 1 },
    totalLikes: { $sum: "$likesCount" },
    avgLikes: { $avg: "$likesCount" }
  }},
  { $sort: { totalLikes: -1 } }
])
Case 3 — Get posts with their author information
Pipeline 
db.posts.aggregate([
  { $lookup: {
    from: "users",
    localField: "userId",
    foreignField: "_id",
    as: "author"
  }},
  { $unwind: "$author" },
  { $project: {
    _id: 1,
    caption: 1,
    likesCount: 1,
    author: "$author.name"
  }}
])
Case 4 — Dashboard: top posts + category statistics in one request
Pipeline 
db.posts.aggregate([
  { $facet: {
    topPosts: [
      { $sort: { likesCount: -1 } },
      { $limit: 3 },
      { $project: { caption: 1, likesCount: 1, _id: 0 } }
    ],
    categoryStats: [
      { $group: {
        _id: "$category",
        count: { $sum: 1 },
        totalLikes: { $sum: "$likesCount" }
      }},
      { $sort: { totalLikes: -1 } }
    ]
  }}
])
✓

Pipeline checklist: $match early when possible → reshape with $project/$set → join with $lookup when needed → group with accumulators → $sort → $limit → final projection. The exact order depends on the question.

Aggregation Revision Map

Need Stage / operator Think
Filter documents $match WHERE
Group documents $group GROUP BY
Choose/reshape fields $project SELECT / reshape
Add a calculated field $set / $addFields compute + keep document
Order $sort ORDER BY
Take N $limit TOP N
Pagination offset $skip skip earlier results
Array to documents $unwind one array item per document
Join collections $lookup LEFT JOIN
Parallel reports $facet multiple pipelines
Count $count / $sum: 1 how many?
Final mental model

Aggregation = data flowing through stages. Each stage receives the previous stage's output. Your job is to decide what the data should look like after every step, then build the smallest clear pipeline that produces the API result you need.
